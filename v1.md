# Restaurant Management System - Version 1.0 (MVP)

Welcome to **Version 1.0** of the Restaurant Management System! 🚀
This document summarizes the complete end-to-end architecture, tech stack, and features that have been implemented in the MVP phase.

## 🏗️ Architecture & Monorepo Structure

The project is built as a highly scalable monorepo using **npm workspaces**. It is divided into customer-facing applications, internal staff dashboards, and a robust backend service.

### 1. Customer Web App (`apps/customer-web`)
The primary interface for restaurant guests to browse the menu and place orders.
- **Tech Stack**: Next.js 16 (App Router), Turbopack, React, TypeScript.
- **Styling**: Tailwind CSS v4 for a premium, glassmorphic UI design.
- **State Management**: `zustand` (with `persist` middleware for local storage cart).
- **Features**:
  - Dynamic Landing Page & Menu fetching from the database.
  - Interactive sliding Cart Drawer.
  - Frictionless Checkout (No login required, Table Number integration).

### 2. Admin Panel (`apps/admin-web`)
The operational dashboard for restaurant managers and owners to track business health.
- **Tech Stack**: Vite, React, TypeScript, Tailwind CSS v4, Lucide Icons.
- **State Management**: `zustand` (Auth storage).
- **Features**:
  - Secure Login with JWT Authentication.
  - Live Dashboard showing Today's Revenue, Total Orders, and Active Tables.
  - Fetching real-time aggregation data from the NestJS REST API.

### 3. Chief Panel / KDS (`apps/chief-web`)
The Kitchen Display System (KDS) used by chefs to manage active orders.
- **Tech Stack**: Vite, React, TypeScript, Tailwind CSS v4, `socket.io-client`.
- **State Management**: `zustand` (Auth storage).
- **Features**:
  - Secure Login with JWT Authentication.
  - **Real-Time WebSockets**: Instantly receives and displays incoming orders without page refreshes.
  - Displays special instructions, quantities, and table numbers.

### 4. Backend API (`services/backend-api`)
The core engine powering the entire system.
- **Tech Stack**: NestJS, TypeScript, Prisma ORM.
- **Database**: PostgreSQL (currently running locally).
- **Features**:
  - **Auth Module**: `passport`, `bcrypt`, and `@nestjs/jwt` for secure Staff login and API route protection.
  - **Orders Module**: Transactional processing of orders, automatically calculating totals, decrementing stock, and saving order items.
  - **WebSockets Gateway**: Uses `@nestjs/websockets` to instantly broadcast `newOrder` events the millisecond an order is placed.

---

## 🔗 End-to-End Flow

Here is how the entire system communicates in real-time:
1. **Guest Orders**: A guest at Table 5 opens the Next.js `customer-web` app, adds a Butter Chicken to their cart, and submits the order.
2. **REST API**: The Next.js app sends a `POST` request to the NestJS Backend (`/api/orders`).
3. **Database Transaction**: NestJS uses Prisma to create the order in PostgreSQL and adjusts the ingredient stock.
4. **WebSocket Broadcast**: Upon successful save, the NestJS `OrdersGateway` emits a `newOrder` event.
5. **Kitchen Display**: The Vite `chief-web` KDS catches the socket event and smoothly animates the new order onto the chef's screen in real-time!
